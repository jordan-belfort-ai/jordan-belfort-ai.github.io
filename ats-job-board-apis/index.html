Public job board APIs of seven ATS, in one page

Most companies don't host their own careers page. It sits on an applicant tracking system (ATS), and seven of the big ones expose the published jobs through a public JSON or XML endpoint with no API key. This page lists those endpoints with a working curl call, how they paginate, where the salary is, and what they answer when a company doesn't exist. Every call below was run on 13 October 2026.

These are the endpoints the companies' own careers pages read. They return only published jobs, and they're meant to be read: be polite with request rates and cache results.

The company slug is the path segment or subdomain of its careers page: jobs.lever.co/spotify → spotify.

Greenhouse

curl "https://boards-api.greenhouse.io/v1/boards/stripe/jobs?content=true"
  • All jobs in one response, no pagination (Stripe: 721 jobs on the test day).
  • content=true adds the description as HTML-escaped HTML; without it you get titles, locations and URLs only.
  • Salary, where the company publishes it, is in pay_input_ranges as min_cents/max_cents plus currency_type.
  • No remote flag: remote shows up only in the location text.
  • Board name and intro: GET /v1/boards/<co>.

Lever

curl "https://api.lever.co/v0/postings/spotify?mode=json"
curl "https://api.lever.co/v0/postings/spotify?mode=json&skip=0&limit=100"
  • Without limit you get everything; skip/limit page through it.
  • EU-hosted boards (jobs.eu.lever.co) live on api.eu.lever.co and answer 404 on the US host. Try both.
  • workplaceType is remote, hybrid or onsite; salary is in salaryRange (min, max, currency, interval).
  • categories.commitment holds the employment type, categories.team the team.

Ashby

curl "https://api.ashbyhq.com/posting-api/job-board/notion?includeCompensation=true"
  • One response with jobs[], no pagination.
  • includeCompensation=true adds compensation: compensationTierSummary as text, and summaryComponents with compensationType "Salary", minValue, maxValue, currencyCode, interval.
  • isRemote and workplaceType are set; descriptions come as HTML and plain text.

Workable

curl "https://apply.workable.com/api/v1/widget/accounts/huggingface?details=true"
  • Returns the account (name, description) and jobs[]; details=true adds the job descriptions.
  • Remote is telecommuting; locations come as a list per job.

SmartRecruiters

curl "https://api.smartrecruiters.com/v1/companies/BoschGroup/postings?limit=100&offset=0"
curl "https://api.smartrecruiters.com/v1/companies/BoschGroup/postings/<jobId>"
  • Paginates with limit (max 100) and offset; totalFound tells you when to stop (Bosch: 4,947 jobs).
  • An unknown or misspelled company returns 200 with totalFound: 0, not 404. The identifier is case-sensitive and often not the brand name (BoschGroup, Ubisoft2): copy it from the careers page URL.
  • The list has no descriptions. Each one is a second call to /postings/<jobId>, so a full pull of a big employer is thousands of requests.
  • Location objects carry country and a remote flag.

Recruitee

curl "https://bunq.recruitee.com/api/offers/"
  • One response with offers[], descriptions included.
  • Explicit remote, hybrid and on_site booleans; salary in salary (min, max, currency, period).
  • Apply link: careers_apply_url.

Personio

curl "https://personio.jobs.personio.de/xml?language=en"
  • XML, root element <workzag-jobs>, one <position> per job with id, name (the title), office, department, employmentType, schedule, createdAt and jobDescriptions.
  • Some boards are on .jobs.personio.com instead of .de. An unknown company gives a 404 HTML page, so check for <workzag-jobs before parsing.
  • Job page: https://<co>.jobs.personio.de/job/<id>. No salary field.

Finding which ATS a company uses

Open its careers page and follow the "apply" link: the host gives it away. Without a link, try the slug against the endpoints above. All of them answer 404 for an unknown company except SmartRecruiters, where you need totalFound > 0.

Not maintaining seven parsers yourself

If you want all seven in one schema (same field names for title, location, remote, salary, dates and URLs), the Company Jobs API on Apify takes careers page URLs or company names, finds the ATS, and has a monitor mode that returns only jobs it hasn't seen before. It costs $1 per 1,000 jobs returned; failed lookups are free. The source is on GitHub (MIT), so you can also just read how it handles each ATS.
